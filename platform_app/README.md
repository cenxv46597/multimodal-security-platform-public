# 多模态安全分析平台：本地研究原型

在项目根目录运行：

```powershell
python platform_app/server.py
```

打开 http://127.0.0.1:8765 。服务仅监听本机，面向可信本机使用，不具备用户认证，不应暴露到公网。

## 本地复评

在“配置评测”中依次选择“对抗鲁棒性与迁移 → 已有变化图与随机对照 · 单图本地复评 → SAR 已使用开发图 · 1 张 → InternVL2B · 本地目标复评”，即可主动启动一项固定的本地复评：对一张已使用的SAR开发图，以及先前生成的单步变化图和随机对照，依次调用本地SARChat InternVL2.5-2B。图像、对应协议及哈希来自既有12图开发实验，启动时检查文件哈希；原始文件不覆盖。本次**不生成新的扰动图**，不涉及闭源目标或未冻结测试候选。一个样本不能证明稳定迁移或整体安全。

后台每次创建独立任务及三项独立子目录，保存协议、日志、原答和状态；SQLite保存在 `.work/platform_execution_v1/jobs.sqlite3`，调用产物在 `runs/vision-safety-capability-preflight-20261114/platform-reeval-<任务ID>/`。任务逐项执行，失败或超时立即停止，不自动重试。用户可按“停止任务”；窗口/服务重启后未完成任务显示中断，不自动恢复。相同时间只允许一个任务。

启动前及各调用前检查 `nvidia-smi` 显示空闲；WDDM下该读数不保证整机流畅，请先保存工作、关闭GPU密集程序。模型此前峰值PyTorch预留约5 GiB，资源不足会失败。每项使用单独的准备、加载和推理阶段时限及总时限；输出达到长度上限或不能明确解析时记无法判断。自动判读只覆盖简短单一类别，需人工审阅；本系统没有经过领域验证的模型裁判。

结果报告使用确定性文字，不调用DeepSeek。DeepSeek书面报告、云端模型、自选数据/模型、新扰动生成及导出尚未接入。网页提供的“开始测试”会真实启动GPU模型，测试任务前请确认资源；用户此前已启动过一次该固定组合，三项完成。当前界面调整期间未再次运行模型。

## 历史报告

首页“多源迁移与闭源评测（11/24–11/26）”通过只读 `/api/latest-results` 展示：17 图 8/255 四条件、17 图 16/255 单源与双源对照、两家云端模型的 17 图原图能力、百炼完整及豆包未完成的闭源配对、14 图提示开发，以及两批四图工程探索。各卡片保持各自样本与分母，豆包零样本未执行会显示“暂无完成结果”；错分和预设类别命中分列。报告展示先前运行结果，不发起 GPU 或云端调用，也不提供新增攻击调度。

接口校验固定的汇总文件哈希、相关原答记录哈希、本地扰动图哈希及关键分母，缺失或不一致返回 503。哈希和记录一致不证明参考标签、场景独立性或供应商模型版本不变。该入口依赖本机 `runs/` 和 `.work/` 下相应历史材料，缺失时不可用；工程样本仍按暂定参考与非独立研究范围展示。

原有选项与 `/api/report` 继续查看12张开发图的历史结果；`/api/clean-report` 展示四模型81张开发图的历史问答。两者均不是独立测试；过去记录未改变。网站不暴露测试候选。

12图历史报告读取已有三条件协议、两模型原答及单人语义记录，每次读取核对36个输入文件哈希、协议哈希、72条回答及截断标志；不一致时拒绝生成该报告。报告展示各条件计数和变化图与随机对照的同图配对、逐条原答与既有判读。核对证明记录间一致，不证明标签正确、单人语义判读正确或文件来源独立；不调用模型，也不构成新实验。此功能面向这组固定历史文件，不是通用实验导入器。

12 图历史报告在统计上方显示书面安全分析。网页通过规则模板将已核对的计数、同图比较和异常原答组织为评估结论、mPLUG 风险、InternVL2B 迁移证据和局限。页面注明生成方式，当前仍使用本地规则模板。

首页「历史实验书面报告」提供两份本地示例，分别对应 12 图扰动和 6 图图片文字注入。两个只读端点 `/api/report-inputs/perturbation` 与 `/api/report-inputs/injection` 均返回 `facts`（实验范围、执行状态、条件判读、带分母的指标、证据编号和解释规则）、`example`（书面段落与指标引用）及 `evidence`（本地逐条记录）。页面直接按指标引用填入数字，可按编号回查原答。示例校验覆盖指标编号、证据编号及分子分母的取值范围，自由文本的事实或推理仍需要人工复核。

注入适配器核对最终 36 条调用及相应单项协议和图片哈希，并复核早期 30 条对应原答的一致性。早期记录不纳入本报告分母。独立转写和标记出现按字符串统计，分类判读只解析这批保存的简短回答。两个案例都是固定的历史开发实验，验证范围限于已完成的记录。报告输入目前只供本机使用，完整接口包含原答和本地证据路径，后续接入报告 API 时需单独定义可外发字段。

报告 API 的候选输入可以在本地审阅。将以下命令的 `injection` 换成 `perturbation` 即可审阅另一组。

```powershell
python platform_app/report_generation.py injection --preview
python platform_app/report_generation.py injection --simulate
python platform_app/report_generation.py injection --response-file draft.json
```

预览只投影实验范围、按条件汇总的状态和判读、指标及分母和撰写规则。样本名、原答、图片、文件路径和逐条证据映射留在本地。模拟用预写示例验证返回 JSON 格式。报告段落引用指标编号，由平台填入数字、证据和原有局限。格式校验拒绝未知编号、额外字段和正文中的十进制数字，仍需人工判断正文主张是否得到证据支持。三个命令均为离线操作。

首次真实 DeepSeek 试验从项目根目录运行 `python platform_app/report_generation.py injection --deepseek`。仅发送六图注入的预览汇总。命令优先读取当前进程的 `DEEPSEEK_API_KEY`，也可在交互式终端按提示隐藏输入密钥。命令发起一次请求，结果通过结构和引用校验后标记为待人工复核。

首页「历史实验书面报告 → 6 图图片文字注入」会读取 `.work/deepseek-injection-report.json`，重新核对保存的指标值、分母和原答编号。原草稿与人工复核补充分别显示。本地规则模板仍可展开，草稿缺失或校验失败时默认展示模板。查看报告为本地只读操作。

## 验证

2026-11-26 联调核验范围和演示步骤见 本地未公开的联调记录。本轮模拟覆盖 HTTP 任务成功及失败停止；提交状态不明时前端禁止重复提交，历史报告核验失败时隐藏旧结果。本轮未重新运行真实 GPU 模型，既有一张图的历史结果和协议哈希已复核。

```powershell
python -m unittest discover -s tests -p 'test_platform*.py' -v
```

测试用模拟执行检查任务创建、持久化、失败停止、恢复、同源POST限制和报告口径；不启动权重或GPU。本次界面改造通过模拟调用验证；此前固定组合已有一次真实运行记录，不能代表所有机器或负载条件。

界面按“配置评测 → 任务进度 → 安全分析报告”展示，原答收在“查看测试详情与原始回答”中。选择12图历史报告不会启动模型；选择单图本地复评并点击“开始测试”才会启动。后端会再次校验配置，不兼容的选项无法通过接口启动。已有的最近一次完成结果会在打开页面后展示。

前端逻辑检查：`node tests/test_platform_frontend.cjs`，使用模拟接口数据，不启动模型。

## 数据集浏览

首页“数据集浏览”提供两批已有SAR开发集：81张模型筛选图、332张扩充开发图，支持类别筛选和分页。分类标签来自既有协议和语义记录，标签及场景仍需复核；这些不是独立测试集。接口只登记两批开发图，按固定索引读取并校验原始图片哈希，不接受用户传入本地文件路径；243张未冻结测试候选不在浏览范围。服务仍只供可信本机使用，不应公开部署。

## 批量复评后端（开发中）

后端任务接口支持通过 `sample_indices` 指定已有12图开发实验中的1至12个不重复索引（0–11），每张依次复评原图、已有单步变化图及随机对照。未指定时仍默认为第一张，当前网页入口仍固定单图，不提供批量选择。历史数据及三类图像哈希会逐项核对，不使用243张测试候选、不生成新攻击。

每个样本和条件的结果还会以独立行写入SQLite `job_results`，并与任务快照在同一事务内保存；原 `jobs` 表及已有任务保持兼容。完成时按条件统计正确、错误、无法判断，并记录变化图和随机对照的同图错误重合；发生失败或中断时保留已完成结果，不自动重试。

批量路径目前只通过模拟调用和文件哈希检查验证，尚未进行真实批量GPU测试；不能视为已验证所有样本、性能或实际运行条件。每项仍独立加载模型，整批可能耗时较长。未来如需真实批量测试，必须先按具体样本和设置取得用户指示，重新检查GPU和其他程序。

任务查询对包含计划信息的新格式快照提供 `progress_summary`：各条件分别列出计划、完成、失败或中断、无结果记录，以及已完成项中的正确、错误、无法判断；配对统计单列缺少完成结果的样本。无结果记录可能是尚未调用，也可能是执行后保存失败或进程中断，不能断言未启动；无法判断属于已完成回答的判读结果，不包含调用失败。汇总由任务快照计算，不会给旧格式任务虚构明细；当前网页尚未展示这一部分汇总。明细和快照在一个事务保存，保存失败不会把未落库结果写入后续快照。本功能仅经模拟验证，并不意味着真实批量运行已验证。

## 合成图文与模拟两阶段历史观察

首页“历史实验书面报告 → 合成图文与模拟两阶段观察”读取本机已完成记录，逐项核验固定总协议和原始结果哈希、单项协议、问题、图片哈希、完成／截断状态及复用的 OCR 结果；不一致或缺失时拒绝展示。页面分别显示图文阶段 6 项和文字阶段 4 项的计划、完成和逐条实际问题、原答及来源。文字阶段使用实验者提供的可信视觉观察，并将图片文字在同一用户消息内标注为低信任；不是实时串接的 Agent、系统级隔离或 SAR 实验。单例未出现目标回答不证明防护有效。此入口只读，不发起模型调用、不触及未冻结测试候选，不是通用实验导入或攻击调度。

本入口经平台 Python 单元测试及模拟前端检查；包含对篡改历史原答时拒绝生成报告的测试。既有单图真实复评和模拟批量执行的验证范围不变。

2026-11-18 对该入口进行了本机浏览器只读验证：可以打开报告，看到图文和文字阶段的分母、原答与限制；修正了文字阶段标签重复问题。验证未点击模型执行入口，测试用临时本机服务已停止。失败分支通过本地 HTTP 模拟错误验证，未篡改真实实验记录。


公开仓库不包含历史报告依赖的本地 runs/、.work/、原始图像和模型权重。干净克隆后相关数据接口将返回不可用；公开汇总见 [2026-11-26 实验记录](../experiments/records/2026-11-26/README.md)。
